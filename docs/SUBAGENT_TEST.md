# subagent 接入实测手册（测试者版）

## 模型

子代理对测试者而言是一次函数调用——给一段输入提示词，取回一次输出；没有等待，没有跨次会话记忆。子代理的生命周期仅在测试期间，它的记忆文件与它同生共死。两条铁律：

一 状态外化：子代理的连续性依赖一个明文记忆文件，命名 memory_of_<子代理名>_<yymmddhh>.md——归属与时刻写进文件名，一轮一档，测试结束随 R 表归档后删除，绝不延续到下一轮。每次调用的模板都要求：开始先读它，结束前把本步操作、请求、响应、结果与卡点从繁从细追加进去。邮箱承载结果，记忆文件承载过程——复盘需要的是过程。

二 仅凭 https：本测试的目的就是验证无 MCP 接入。子代理只可用通用计算工具发起 https 请求（curl 或等效），不得使用任何 MCP 网关或现成邮件工具。测试宿主若自带这类工具，必须在提示词中显式禁用，否则测试无效。

## 前置

- 测试者注册一个全新账户专供子代理：名称与密码都要有充分随机性（不可延续、不可猜测），一轮测试一个，不复用。
- 按命名规则创建本轮唯一的外部记忆文件，例如 memory_of_subagent-t1_26083021.md：整个测试从头到尾只用这一个文件；进入测试时它必为空（新建即空）；记录从繁从细——每步的操作、请求、响应、结果与卡点都写入；完成测试后随报告归档并删除。
- 确认测试宿主环境中子代理无法或不得使用 MCP 工具。

## 调用序列

每步固定为：发调用、取输出、按判据验收、测试者自查、记录进 R 表。任一判据失败或子代理输出卡点，记录后中止该分支，不即兴补救。

统一模板前缀（每次调用都带）：
邮箱 <addr>，密码 <password>，服务 https://<domain>。约束：只可用通用 https 请求与服务交互，禁止使用任何 MCP 或现成邮件工具。记忆：先读 <memory_of_..._.md 的绝对路径> 恢复上下文，结束前把本次操作、结果与卡点追加进去。

### T1 报到

前缀 + 任务：自述端点 /api/self。请按自述文档完成认证，给 <tester-addr> 发一封报到信。完成后仅输出：已发送，或失败原因与卡点。

判据：输出为已发送；测试者收件箱收到报到信；记忆文件有本步记录。

### T1.5 测试者发信

测试者给子代理发一封信，主题内容任意，例如：请在本话题下回信。此信是 T2 的对话对象。

### T2 话题回执

前缀 + 任务：你的收件箱有一封来自 <tester-addr> 的来信，读取它，并在同一话题下回信。完成后仅输出：已回复，或卡点。

判据：回信的 in_reply_to 等于测试者那封信的 id；记忆文件有本步记录。

### T3 附件

前缀 + 任务：生成一个小文件，计算其 sha256，上传并随信发给 <tester-addr>，信中写明该 sha256。完成后仅输出：已发送与 sha256，或卡点。

判据：测试者下载附件，本地 sha256 与申报一致；记忆文件有本步记录。

### T4 从属声明

前缀 + 任务：将你的账户声明从属于 <tester-addr>。完成后仅输出：已声明，或卡点。

判据：测试者的从属列表出现子代理账户；记忆文件有本步记录。

### T5 文档复盘

前缀 + 任务：通读你的记忆文件，把其中全部卡点、不确定与文档未覆盖之处逐条编纂成清单，以一封信发给 <tester-addr>，主题标明文档复盘。

判据：复盘信到达且逐条成列——这是自述文档缺陷清单，来源是各步真实记录而非事后回忆；重演与虚构都被此设计排除。

## R 表与报告

每次调用记录四项：模板号、输入全文、输出全文、判据结果。终局汇总 R 表、T5 缺陷清单与记忆文件本体（按其命名归档），交总师或落 issue。

## 验收口径

- 全序列零即兴提示：测试者只使用模板与前缀。
- 子代理的每次卡点都是自述文档的缺陷信号，如实记录。
- 报告含 R 表与记忆文件原始记录。
- 若测试宿主无法禁用 MCP 工具，本测试在该宿主无效，须换宿主执行。
